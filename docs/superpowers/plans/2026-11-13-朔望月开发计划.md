# 朔望月开发计划 · 从单人牌桌到可分享的试玩版

**目标**　让第一次接触朔望月的人，在手机或电脑浏览器打开一场游戏，读懂开局判例，独立完成八手下注，并在复盘中看懂哪条证据能解释胜负。

**设计依据**　[基础模式试玩规则](../../../朔望月-基础模式试玩规则.md) 是牌表、比较顺序、下注、挑战、验牌和提示的依据。

**当前进度**　[双击试玩版](../../../dist/朔望月-双击试玩.html) 已实现八手单机、新手指导、本地续局、推理复盘和秘密换牌。v0.5 增加分享入口，并提供可转发的离线 HTML 与可部署的静态网页包。已完成[四种程序策略的试玩基线](../../试玩基线-v0.3.md)，真人试玩仍待收集。

**实现选择**　按一名熟悉 TypeScript 的开发者、浏览器单机、先使用文字牌面估算。推荐 TypeScript 写裁判和对局状态，React 与 CSS 做牌桌，Vite 启动和构建，Vitest 验规则，Playwright 验浏览器流程。第一版可以作为静态网页本地运行。数据库、登录、模型服务、联机和画面引擎均无需成为开工依赖。

## 第一版的玩家体验

1. 点“入局”，看到八手目标、双方各32道、一条公开判例和三套候选规则。牌面显示固定日期与拆位数字。初次玩家可以按需依次使用三档提示。
2. 进入桌面。上方是地猴的明牌与盖住的暗牌，中间是公共牌、底池、手数和当前行动方，下方是自己的两张牌与行动按钮。按钮写明实际还需付多少道，例如“跟注，补1道”。
3. 玩家可以随时看开局判例、翻已公开的记录、勾选自己的猜测。每半场的一次挑战绑定本次开注或加注。弃牌结算后、下一手前可用全场唯一一次验牌。两个机会分开显示。
4. 继续到第八手。整场筹码结果与隐藏规则同时揭晓，可按手回看首个决定胜负的指标。再开一场重新抽规则、判例与牌序。

**首版的屏幕量**控制为开局、牌桌、结算三个页面状态。规则册、笔记和历史可以是牌桌上的可展开面板。首版就保证字号、触控面积、当前行动方和暗牌可见性；插画、翻牌动画、音效与场景氛围排在真人试玩之后。

## 阶段一　先让一手牌跑通

- [ ] **建牌表和裁判。** 在 `src/game/cards.ts` 录入规则稿的36张牌，以独立 ID 区分日期相同的小寒和腊八。在 `src/game/rules.ts` 提供 `compareHands(rule, publicCard, playerCards, dealerCards)`，返回胜方或平局、双方各项数值、首个分胜负的指标。裁判统一用于地猴判断、开局判例、验牌和最终复盘。
- [ ] **先用实牌核算。** 在 `tests/rules.test.ts` 固定“公共春节，甲重阳＋除夕，乙中元＋腊八”。三种规则依次应得甲、乙、甲，甲的四连只在大数和近数决定胜负。另验零起头的顺子、9不接0、重复数等频时选较大数字、距离对称以及完全平局。此前的565万余种摊牌枚举用作牌表或裁判变更后的核对基线。
- [ ] **接通一手下注。** 在 `src/game/match.ts` 建立每手阶段、行动方、双方已投筹码和底池，用 `legalActions(state)` 列出合法动作，用 `applyAction(state, action)` 执行。React 只发送意图和显示结果。先用指定牌序与脚本庄家验证过牌摊牌、开注跟注、加注后弃牌。
- [ ] **在浏览器走完一手。** 显示双方32道，双方付底注后应各剩31道、底池2道。玩家开注1道、庄家跟1道，底池应为4道。若玩家赢，结算为34道对30道。连续点击结算按钮，只能派彩一次。

**交付检查**　用开发测试入口切换三种规则，复算同一桌牌；再用鼠标或触屏打完一手。这是开发里程碑，隐藏规则体验在阶段二成形。

## 阶段二　完成八手的最小可玩版本

| 顺序 | 开发任务 | 完成条件 |
|---|---|---|
| 2.1 | 扩展 `match.ts`。每手从完整牌组重洗，发五张不同牌；首手玩家先，逐手交替。第1–4手的单位为1道，第5–8手为2道。 | 从第4手跨到第5手时，下注单位、先手和挑战次数各更新一次。任何时刻双方余额加底池共64道。 |
| 2.2 | 在 `src/game/clues.ts` 加入规则稿的三个基础判例。整场等概率抽一条规则，再从两条兼容判例等概率选一条。用裁判核对每条判例并提供数字帮助。 | 开场总能从三套候选排除一套。同一条判例能出现在两种相容规则下；同一场的后续发牌均沿用已抽规则。 |
| 2.3 | 在 `src/game/dealer.ts` 实现 `chooseDealerAction(view, legal, rng)`。输入仅有已发五张牌、本场规则、余额、下注和公开历史。挑战由状态机强制跟注并摊牌。 | 庄家能基于真实强弱开注、诱跟或诈唬。固定它能观察的数据及随机输入，改变下一手牌序或玩家笔记，当前决策一致。 |
| 2.4 | 在 `src/game/views.ts` 生成玩家视图，`src/ui/Table.tsx` 消费该视图。开局规则册、免费帮助、猜测笔记和可查看的历史进入牌桌。 | 玩家可以推理却无法从牌背、按钮、读屏标签或复盘预览读出暗牌与本场规则。普通摊牌只显示公开牌面和胜负，详细裁判解释留到终局。 |
| 2.5 | 接入挑战与验牌。用“挑战并开注”“挑战并加注”明确实际支出，一次提交，一次扣款。弃牌后在继续按钮旁给出验牌入口。 | 挑战后庄家无弃牌机会；前半场未用额度到第5手过期。验牌只揭牌和记录假想胜负，不改变刚刚结清的余额。 |
| 2.6 | 在 `src/ui/Review.tsx` 显示净收益、胜平负、隐藏规则和逐手记录。弃牌获池与按牌力获胜用不同措辞，验牌记录标记为假想摊牌。 | 第八手结算后才能揭晓规则；“再来一场”清空旧笔记、次数和历史。固定相同输入能复现同一场。 |

**一个可执行的初始庄家。** 可以先按真实牌力领先、平手、落后三档选动作。无人开注时，领先有时过牌诱跟，落后有时开注诈唬。面对开注时，领先在跟注与加注间选择，落后以弃牌为主、少量加注施压。面对最后一次加注，领先跟、落后弃。平手按当下合法动作选择过牌或跟注。所有频率集中在一份配置中并写入开发回放。首版用这样的简单对手即可验证闭环，具体频率留给阶段三对照实验。

**首版交付检查。** 建议配置 `npm run dev`、`npm run build`、`npm test` 和 `npm run test:e2e`。用 Vitest 检查筹码守恒、平局、最后一手极限投入和非法操作；用 Playwright 在正常入口跑完三种规则的固定种子场，覆盖挑战、验牌、再开一场。另请一位首次接触游戏的人自行完成一场，把需要开发者代为解释的位置记下来。

## 阶段三　用试玩决定优先改哪里

- [ ] **先做小规模对照。** 建议首轮找4–6人，每人两场，一场使用固定牌序便于定位问题，一场使用新牌序观察迁移。交错安排顺序。如果固定场与前一场使用相同判例，记录玩家是否靠记忆识别，以免把熟悉题目误判为学会规则。
- [ ] **把“没证据”和“看不懂证据”分开。** 记录第一手足以区分剩余两种规则的公开判例何时出现、玩家何时确认、引用的是哪手，以及此后有没有改变下注或挑战。只按实际公开的牌面推算可排除的规则。玩家八手都没见到区分性证据时，优先调验牌机会或线索，已有反例仍理解困难时，优先改拆位展示与历史回看。
- [x] **建立程序策略基线。** 相同规则、牌序和庄家随机输入下，对照四种只用玩家可见信息的策略。记录净收益、挑战、摊牌率和证据出现手数。
- [ ] **把程序基线与真人决策一起看。** 从终局下载的记录复核判断时机，并补记玩家实际采用的证据和下注理由。
- [ ] **一次改一件事。** 若玩家看到地猴开注就弃、且通常因此受益，先调庄家诈唬与诱跟频率。若玩家有依据、也愿意下注，却总忘记挑战，先调操作提示；若挑战时机合理仍很少产生收益，再调额度。顺子容易误读时，先用规则稿内的春节判例教学。24与28的目标差异单独做比较场。

**退出条件**　新玩家能不靠口头指导打完八手；至少能复述一个排除依据，并说明一次由此改变或坚持的下注决定。若缺少这种案例，继续迭代对应环节。首轮小样本用于定位问题，不能据此认定长期胜率已平衡。

## 阶段四　把已验证的牌桌做得好用

1. **先解决手机读牌。** 在手机宽度对照检查两手个人牌、公共牌和行动区。优先呈现牌名、日期数字、当前要补的筹码。历史记录收起后仍能一键回看；明暗、胜负、可挑战状态都有文字或形状标识。
2. **补齐连续游玩体验。** 每次合法动作后保存一个带版本号的本地快照。测试在待行动、挑战已提交、弃牌待验牌和终局刷新，恢复同一手、同一额度和已结账的余额。旧版或损坏的存档应让玩家可重新开局。
3. **最后增加视觉表达。** 按牌名、日期、数字三层排版制作纸牌；桌面用木盒、筹码和翻牌动作表达发牌、下注、揭晓。基础模式整场规则固定，月相装饰应避免暗示第4手会换规则。加入可关闭的动效与声音，快速操作和减少动态效果时结算保持一致。
4. **准备可分享的版本。** 生成静态构建，做桌面鼠标、键盘和手机触屏完整回归。用真实手机验证牌面能读清、按钮不被历史面板遮挡、返回后能续局。交付本地构建与运行说明；托管发布可作为单独里程碑。

## 阶段五　按试玩结果选择扩展

| 已观察到的需求 | 下一项值得做的内容 | 开启条件 |
|---|---|---|
| 熟悉三条开局判例后，首次推理太短 | 扩充判例库、加入固定种子每日挑战 | 新判例经裁判验证，抽取机会不额外泄露规则 |
| 资深玩家想重新体验规则变化 | 单独设计带可观察提示的月相切换模式 | 能给出切换前后的有效证据，并在复盘解释 |
| 玩家希望组桌互相下注 | 多人房间原型、服务器裁判、私密发牌与重连 | 先重写多人下注与平局分配约定，再安排网络开发 |

**接下来收集首轮试玩。** 用 [v0.3 的真人试玩表](../../试玩基线-v0.3.md#真人首轮) 记录固定场与随机场。先看玩家能否解释重数局证据，再按观察结果决定调整线索、教学还是庄家。

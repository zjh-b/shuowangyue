# 朔望月 · 八手之间

[在线试玩](https://zjh-b.github.io/shuowangyue/) · [离线试玩 HTML](https://zjh-b.github.io/shuowangyue/%E6%9C%94%E6%9C%9B%E6%9C%88-%E5%8F%8C%E5%87%BB%E8%AF%95%E7%8E%A9.html)

离线版包含插画、界面和配乐。打开离线版页面后，可点「分享 → 保存试玩文件」或用浏览器将 HTML 保存到本地。

每场从三种规则抽一套，八手内固定。先看开局判例，再用摊牌和验牌验证判断。地猴知道规则，也看得见暗牌。玩家每半场可随开注或加注发起一次挑战，让地猴必须跟注。八手结束后按筹码判断胜负，并公布实际规则。

点击「入局」会先打开规则介绍。可以直接开始，或在三步新手指导中练习读牌计分、用判例排除规则和挑战摊牌。练习单独结算，牌局中也可从「规则册 → 新手指导」重看。

第 5–8 手轮到你首次行动时，可以秘密换一次暗牌。从未发牌中随机抽一张，地猴按旧牌下注，摊牌和验牌按新牌判定。换牌后仍可用本半场的挑战。摊牌或验牌提供区分证据时，可直接在结算区展开规则对照。

页首「配乐关」可开启循环背景音乐。音乐使用 Kevin MacLeod 的《Eastminster》，原曲重编码为低码率 MP3，内置于离线版。「规则册 → 配乐署名」也可查看来源和许可。[作者与原曲](https://www.incompetech.com/music/royalty-free/index.html?isrc=USUAN1100719) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。

## 提示与续局

基础模式每场提供三次免费提示，可以在开局或出牌时按顺序使用。第一次整理总点数、重数和顺子，第二次排除与开局判例不符的法则，第三次优先引用一手已公开、能区分剩余法则的牌例，证据不足时补一条判例并给出答案。已查看的提示可以反复回看。

牌局、挑战和验牌额度、提示次数与笔记都保存在当前浏览器。同一浏览器重新打开同一路径时可以续局。移动离线文件或换浏览器时，原来的进度通常需要回到原路径和浏览器查看。

## 双人与四人联机

点首页「联机对局」，选双人桌或四人桌，填称呼后建房。把邀请链接或房间码发给朋友，各自在手机或电脑入座，坐满后由房主开始。刷新或重新打开房间链接时，同一浏览器可回到原座位。房间最后一次操作 24 小时后过期。

真人桌开局共看一条判例。八手使用同一套隐藏法则，每人 32 道，每手付 1 道底注，轮换先手。前四手下注单位为 1 道，后四手为 2 道，每手最多加注一次。仍在牌局中的玩家都响应后摊牌。弃牌暗牌保持盖着。并列平分，余下的整道从本手先手起依次发给并列赢家。最终筹码最多者获胜。

第 5 手起每人有一次秘密换暗牌，须在该手首次行动前使用。每次行动有 60 秒，超时自动过牌或弃牌。真人桌的线索区可展开规则对照和公开摊牌证据。

### 自行运行联机版

使用 Node.js 24+。

```powershell
npm ci
npm run build
npm run start:rooms
```

同源网页和接口默认位于 `http://127.0.0.1:8787/`，房间写入 `.local/rooms.sqlite`。局域网测试可设置 `SHUOWANG_HOST=0.0.0.0`，由朋友访问主机的局域网地址。公开自托管可设置 `PORT` 和持久化路径 `SHUOWANG_ROOM_DB`，由 HTTPS 反向代理转发，并用 `SHUOWANG_PUBLIC_ORIGIN` 设置外部站点源。若前端与接口分开，构建前端时设置 `VITE_ROOMS_API_URL`，并把前端源加到服务器的 `SHUOWANG_ORIGINS` 中。

GitHub Pages 部署通过同名仓库变量 `VITE_ROOMS_API_URL` 指向房间接口。接口须能从试玩网页访问，且 `GET /api/rooms/health` 返回成功。Sites 部署使用 `node scripts/build-rooms.mjs --sites` 生成 Worker，并用 `drizzle/` 下的迁移初始化 D1。单文件离线版的联机入口会打开网页版。

运行 `npm run build` 后，用 `npm run test:rooms` 验证真实服务器上的双人、四人房间。测试使用独立浏览器会话和本地测试数据库。

## 推理复盘

在「笔记」选择一套法则并点「记录判断」。终局可以回看首次和最后判断、当时已用的提示，以及最早能区分候选法则的摊牌或验牌。下载的试玩记录包含玩家可见的牌面、行动和判断，私人笔记留在本地。[试玩基线与真人记录表](docs/试玩基线-v0.3.md)。

## 试玩反馈

牌局中点页首「反馈」，或在终局点「留下试玩反馈」。玩家可以只提交卡点与留言，也可以预览并勾选对局摘要。摘要包含进度、提示次数、判断时点、挑战和换牌手次，终局时另含法则和净收益。摘要省略完整牌序、未公开暗牌、私人笔记和浏览器标识。在线提交只在玩家点击「提交反馈」时发生。

1. 在自己管理的 Formspree 账号创建表单，并复制 Integration 页的表单 ID。 [创建表单](https://help.formspree.io/articles/building-your-form/building-an-html-form)
2. 在 GitHub 仓库「Settings → Secrets and variables → Actions → Variables」新建仓库变量 `VITE_FEEDBACK_FORM_ID`，值为表单地址 `https://formspree.io/f/…` 最后一段的公开 ID。
3. 手动运行「Publish GitHub Pages」工作流。用正式网址提交一条测试反馈，到 Formspree 的「Submissions」核对。

本机可把同名变量写入 `.env.local`，重启开发服务器试用。未配置接收表单时，页面提供「下载反馈」供玩家手动转交。单文件离线版也使用这个入口。

## 本地开发

```powershell
npm ci
npm run dev
```

浏览器访问终端中显示的本地地址。开发模式支持固定种子和指定规则，例如 `/?seed=28&rule=large`。正式构建每场随机抽取规则。

## 构建和验证

```powershell
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

构建会生成静态网页与单文件离线版。浏览器测试覆盖新手指导、三套规则各打八手、窄屏验牌和提示、刷新续局，以及复制单文件后完全离线运行。若已有兼容的 Chromium，可将其路径填入 `SHUOWANG_BROWSER`，再运行浏览器测试。

具体比较方法、牌表、下注约定和先前的枚举结果见[基础模式试玩规则](朔望月-基础模式试玩规则.md)。地猴的策略参数仍待真人试玩校准。

## 分享与发布

本仓库使用 GitHub Actions 构建并部署 GitHub Pages。推送到 `main` 会运行单元测试、构建项目并发布 `dist/`，也可在 Actions 页手动运行工作流。

运行 `npm run release`，在 `release/` 生成带版本号的离线 HTML 和静态网页 ZIP。打包使用 Windows 自带的 `tar.exe`，macOS 或 Linux 环境需要 `bsdtar`。

- **发送文件**。转发离线 HTML 即可。收件人先把文件保存到本地，再用浏览器打开。
- **发送网址**。解压静态网页 ZIP，把根目录的 `index.html`、`assets/` 和署名文件一起上传到静态托管。浏览器访问托管地址后，点页首「分享」即可复制链接。网站可以放在域名根目录或子目录，托管入口建议使用 HTTPS。

分享入口只发送游戏文件或网页地址。对局和私人笔记存放在玩家各自的浏览器中。
